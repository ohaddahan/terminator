# Orca icon inventory and Terminator cosmetic review

Inspected 2026-09-10. Orca source: [`2bf298d1dc1a`](https://github.com/stablyai/orca/blob/2bf298d1dc1a41c03a270e89eca08834c36f13e0/package.json).

## Findings

Orca uses Lucide for its general UI: `lucide-react` is declared as `^0.577.0` and resolved to `0.577.0` in the lockfile. Terminator already bundles Lucide 0.468.0 SVGs, with an Octicons terminal icon and an Orca-derived file mapping. SVG assets can use the existing native egui renderer.

This is a static source inventory: 361 distinct `lucide-react` imported symbol names and 124 `lucide-react-native` imported symbol names across non-test source under `src`, `mobile`, and `cloud`. Names include Lucide aliases, so these counts are not counts of distinct drawings or proof that every icon appears at runtime. Tests/specs/stories and test/fixture directories are excluded. Type-only imports are excluded. Each name below has one example source; some have many uses.

Custom SVG components, bundled brand assets, dynamic repository icons/browser favicons, and dependency-owned Monaco Codicons also exist. Dynamic/user content and icons internal to dependencies are not a finite app-source inventory. Inline-SVG files below include illustrations and SVG strings as well as icons.

## Cosmetic proposals in priority order

1. Replace ambiguous action icons using the mapping above. Keep existing terminal branding; menu consistency does not require replacing it.
2. Give menus a subtle shadow and approximately 6–8 px corner radius. Terminator explicitly disables popup shadows and uses a 4 px menu radius. Orca uses an 11 px outer radius, 4 px inner padding, border, and shadow. Translate the visual hierarchy into native egui; opaque themed surfaces are sufficient.
3. Standardize menu geometry: 14–16 px icon, fixed icon column, 8 px icon/text gap, 26–28 px rows, consistent separators. Our current 16 px icons and 26 px rows are already close to Orca's 14 px icons and 25 px rows; focus on spacing and consistency, not a wholesale resize.
4. Display actual configured shortcuts in the existing right-hand column. Most Terminator actions pass an empty shortcut string. Match platform formatting and overrides; do not advertise unimplemented bindings.
5. Use explicit action styling instead of treating every label beginning Close/Remove/Clear as destructive. Clean editor/image close can be neutral; actual termination/deletion remains red. This proposal changes visual treatment only.
6. Replace remaining text-glyph controls such as + and dropdown chevrons with the bundled SVG equivalents, using consistent hover backgrounds and hit areas. Verify locations against the current checkout because main.rs changed during this review.
7. Improve secondary text: truncate long paths with the full path on hover, align trailing status labels/counts, and reserve the accent for selection/focus. Keep the existing compact pane captions and soft focus outline, which are already implemented.

Local evidence: `crates/app/src/appearance.rs` (`apply`, `menu_item`, `row`, `pane_caption`), `crates/app/src/icons.rs`, `crates/app/src/file_actions.rs`, and current menu call sites in `crates/app/src/main.rs`. Reviewed saved screenshots `docs/screenshots/flat-100/context-menu.png` and `docs/screenshots/focus-and-close/soft-border-editor-closed.png`; these are historical fixtures, not fresh screenshots of the running application. No application code or settings changed for this review.
